    Task 2 : RetailSync Case Study

         Stage 1.Kickoff  

            Specification: Missing - The requirements were only discussed in one meeting and nothing was written down

            Development: Present - The developer started designing the database

            Validation: Missing - There was no checking with users to make sure the requirements were understood correctly.

            Evolution: Missing -  There was no plan for dealing with future changes.

         Stage 2.Dev

            Specification: Weak - The developers were working from their own understanding instead of clear requirements.

            Development: Weak - They built the different modules, but there was little coordination, no code reviews and no shared standards.

            Validation: Missing - Warehouse staff were not involved and there was no proper testing during development.

            Evolution: Weak - The system was being built without much thought about future changes or maintenance.

         Stage 3.Change of Plan

            Specification: Weak -  The second warehouse requirement was added informally and not properly documented.

            Development: Weak -  The team patched the new requirements onto the existing system instead of reviewing the design.

            Validation: Missing - They did not properly check whether the new design would work with the second warehouse.

            Evolution: Weak - A major change was made, but it was not properly managed.

         4.Testing

            Specification: Missing - There was still no clear set of requirements or test cases to test against.

            Development: Present - The team ran the application and fixed some crashes.

            Validation: Weak - They only tested it themselves for two days. Warehouse staff did not test it at all.

            Evolution: Missing - Problems found during testing were not used to improve the overall system properly.

         5.Go-Live

            Specification: Weak - The system clearly did not meet some of the real warehouse requirements.

            Development: Present - The system was released and later patched when problems appeared.

            Validation: Failed - Real users quickly found major problems with transfers, barcodes and simultaneous use.

            Evolution: Present - The team had to make changes after the system failed in real use.

The machine also relied too much on software for safety amnd didnt have enough hardware safety features. there was also very limited softwaree testing and documentation.
